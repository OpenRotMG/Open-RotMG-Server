## Qualified semantic requirements

**Source facts** below come from the pinned DOCX transcription and DECA pages in `sources.json`, plus inspected XML. **Migration choices** resolve unspecified engine details; neither category asserts authenticated 123.5.1 engine behavior. These source facts and authored choices describe the contract, not historical acceptance.

- **States (documented):** first sibling recursively entered; root/ancestor behaviors persist during child changes; transitions target siblings; all active levels execute. Conditions with duration0 persist while their behavior's state is active and are removed on exit. **Choice:** one immutable active path per actor; behaviors in document order, then ancestor-first transitions, first matching transition in XML order, one transition per update. Transition attributes are AND; separate transitions are OR. Exit deepest-first, enter shallowest-first, reset only exited/new local state. Destination updates begin next 50ms tick; initial admission executes once at t0. Parent age is not reset by child changes. Zero-time cycles advance at most once per tick, not recursive busy loops.
- **Buckets (documented):** ordered first-success per named bucket; nonbucket behaviors still run. **Choice:** child path before ancestors (matching the documented chicken example), sharing bucket success for that actor/update; cooldown/stun/no-target returns not-success without consuming RNG or blocking later movement alternatives. Successful emissions consume cooldown exactly once; a cooling attack is not an emission. State exit clears conditions owned by that state, not an overlapping ancestor's copy.
- **Embeds/orders (documented):** expand named blocks/parameters; orders act like stateful behaviors on listeners. **Choice:** lexical object/embed scope; fail unbound parameters/recursive embeds; each expansion/listener has independent clocks/RNG locals. Closest eligible issuer, distance then numeric-ID tie-break; targetIds filter exactly; issuer death/exit invalidates order state. Ordinary tags are actor-local and persist until explicitly cleared or the actor is retired; global tags and order discovery are world-scoped, never cross-world singleton state. Explicit parent/encounter selectors must preserve ownership rather than silently selecting an unrelated encounter. Structural duplication is legal only with independent local identity.
- **Clock/units:** source cooldown/offset/afterTime/duration are seconds, projectile LifetimeMS is milliseconds, angles degrees (0 east,90 south); convert at load, reject nonfinite/negative/overflow. Documented ChangeSize rate is percent per **200ms**: at50ms, rate0.2 changes size0.05, not0.2. Retain fractional remainder and clamp. **Choice:** deadlines use active simulated milliseconds and `>=`, no extra check-before-decrement tick; no catch-up bursts. Stasis freezes AI/behavior-local clocks, stun suppresses Shoot and targeted GrenadeToss/ObjectToss only, as recovered behavior.cc:445,2265,2377 checks it, not other attacks, movement or state ages; failed emission spends no cooldown/draw. Fully dormant actors freeze AI locals; explicit world/lifecycle deadlines (decay, portal expiry, terminal cleanup) remain world-clock services. First waking update does not replay missed attacks. Documented defaults: Shoot targeted/range8/one shot/projectile0/cooldown1s/offset0/jitter=false/predictive0/angle9 degrees; Decay60s, dropLoot=false/giveXP=false; Metamorphose dropLoot=false/giveXP=false; MakeMinions startWithMinions=true, and false still emits one child on the first update (behavior.cc:1064-1095); ChangeSize rate.2/min60/max200. These are qualified documentation defaults, not a license to infer unknown attributes from zero. Missing mandatory child/state/projectile references fail; optional omissions get only a documented or visibly authored default, including historical misspellings only through explicit corrections. Documented DECA offset/offscreen quirks are limitations to avoid explicitly, not a mandate to reproduce bugs.
- **Combat/lifecycle choice:** selected native hit/damage/wire remains authoritative; nearest live target within range, deterministic distance/ID ties, finite walkable movement, elapsed-time scaling rather than legacy NR speed formula. Independent seeded random draws in stable definition/actor/behavior order; sequential random transitions are not normalized weights. Damage eligibility aggregates by durable character identity, capped effective HP damage (not overkill), and transformations transfer the encounter ledger once. Projectile/grenade/decay/simultaneous defeat funnels into one terminal claim; no double XP/loot/clear/portal. Children inherit world/encounter/parent ownership; bounded live caps release on all terminal paths; replacement is not a fresh reward unless XML explicitly grants it. Missing behavior/attribute/asset is a contextual startup error, not inert success.

### Loot allocation: source values versus missing-engine reconstruction

Recovered `Loot`/`SoulboundLoot` rows specify `prob`, `threshold`, `tier`, `min`, `max`; original loot-engine source is absent. Stheno (917) has Bulwark **.001 / threshold .15**, Speed **.3 / min1**, skin items **.10 / threshold .10**; Thessal Mana **.18 / min2**. Beach Bum's recovered Beachzone portal probability is **.7**, not the current .5; Flying Brain's Lab probability is **.02**, not the current .1. These literal values replace prior rates. No claim that threshold comparison, default, guarantees or allocation algorithm has been recovered.

Concrete **authored allocation contract** for later implementation/tests: eligibility is positive aggregated effective damage by a living, nondeparting durable character in the owning world/encounter at defeat; default threshold0; explicit threshold is damage/maxHP, **>= includes equality**, not a percent of total multiplayer damage. Distinct rows (including repeated identical rows) are independent, once per eligible character; success is uniform `u < prob` (u=prob fails). Defaults: prob1, min0, max unbounded by row but encounter safety-bounded; nonnegative integral min/max, min<=max, prob/threshold in[0,1], tier pools must be nonempty. `Loot` is a public row drawn once per death; `SoulboundLoot` allocates private items. Preserve selected-client tiers/slot-class membership; choose uniformly among sorted eligible item IDs, no wiki-tier shift or class favoritism. No eligible contributor means no private draw or guaranteed item.

`min`/`max` are per-row **total encounter allocations**, not per-player guarantees: Bernoulli draws in a seeded fair recipient permutation; truncate successes at max, then top up to min in that same order, first recipients without a success, cycling only if min exceeds eligible count. Items may repeat when min requires it. This makes solo min2 explicit rather than silently discarding an XML value. Repeated rows keep independent minima/caps/draws. A private drop remains owner-only through durable once-only pickup; public ownership is explicit. Export conditional per-row eligibility/roll/min/max/pool semantics from the same evaluator as runtime; don't advertise .3 as an unconditional final per-player chance when min/max or a pool changes it. These choices are visibly authored requirements and must remain labelled as such on restoration/drop evidence; source values alone cannot validate them historically.
